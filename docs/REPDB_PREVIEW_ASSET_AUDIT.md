# RepDB preview: проверка перед интеграцией в FitPulse

Дата проверки: 19 октября 2026 года.

## Что в приложенном ZIP

- ZIP содержит preview-пакет, а не полный коммерческий набор.
- В манифесте preview — 22 упражнения; в `images/animations/` — 22 анимированных WebP мужского набора и в `female/images/animations/` — 22 женских варианта.
- В архиве есть и статические изображения/позы. Файл `exercise-list.json` содержит более широкий каталог названий, но перечисление ID не означает наличие animation-файла для каждого ID.
- Качество визуального примера заметно выше схемной SVG-фигуры FitPulse: прозрачный фон, детальная мускулатура, читаемая техника и отдельные варианты персонажей. Его можно использовать как критерий визуальной приёмки.

## Условия использования

В приложенном `README.md`/`LICENSE.md` preview описан как CC BY-NC 4.0 и предназначенный для оценки/некоммерческого использования. Сам факт, что архив загружен в репозиторий или прислан владельцем проекта, не превращает его в коммерчески лицензированный продуктовый набор. Поэтому анимационные WebP из preview не копируются в распространяемый APK.

Текущие публичные страницы RepDB описывают отдельную коммерческую лицензию на полный набор и отдельно заявляют character options/animation coverage:

- Dataset и состав: https://github.com/RepDB/exercise-dataset
- Продукт: https://repdb.co/
- Лицензия: https://repdb.co/license/

Перед покупкой необходимо сохранить чек/условия лицензии и проверить в них: право встраивания в коммерческий Android APK, локальное/offline-хранение и кэш, распространение через магазины, выбранных персонажей (male/female), количество разрешённых приложений и ограничения на перекодирование/модификацию.

## Совместимость формата с текущим приложением

Текущий mobile package использует Expo SDK 51 / React Native 0.74 и не объявляет `expo-image` в зависимостях. Нельзя просто заменить локальный GIF на `.webp` и считать, что он будет анимироваться: документация React Native отмечает, что GIF и WebP на Android требуют дополнительных модулей, а animated WebP — отдельной поддержки. Перед интеграцией нужно выбрать совместимый рендерер (например, совместимую версию `expo-image`) либо настроить/проверить поддержку Animated WebP через native build, затем подтвердить автостарт/паузу на устройстве.

Технические источники: https://reactnative.dev/docs/Image#gif-and-webp-support-on-android и https://docs.expo.dev/versions/latest/sdk/image/.

## Рекомендуемая интеграция, если коммерческие права подтверждены

1. Не использовать `exercise-list.json` как готовую карту медиа: построить manifest по реальным файлам, стабильным exercise ID, варианту персонажа и фактическому equipment/movement.
2. В мобильном приложении Expo/React Native хранить локальные animation assets и выбирать их по стабильному ID. Не использовать приблизительное совпадение названий и не подставлять близкое упражнение.
3. Утвердить мужской/женский режим, фон, размеры, прозрачность, кадрирование, производительность и поведение offline на настоящем Android-устройстве.
4. Если точной анимации для упражнения нет, показывать качественный постер плюс честно обозначенное отсутствие видео — не повторять движение другой техники.
5. Добавить CI-проверку, чтобы каждый manifest path существовал, каждой approved-анимации соответствовали два варианта персонажа (если они требуются), и coverage считалось только после ручной проверки техники.

## Текущий статус

RepDB preview используется только как референс качества; в APK ничего из его лицензируемых preview-анимаций не добавлено. В FitPulse сейчас реализовано разрешение точных локальных постеров из уже существующей библиотеки; новые анимации для 225 стабильных ID пока не подтверждены и не считаются выполненными. `main` не изменён.
