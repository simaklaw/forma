## 2. Оригинальное 2D-покрытие

Корректный source-derived реестр содержит **739 stable IDs**:

- 66 упражнений планов: 27 домашних и 39 заловых;
- 673 записи импортированного каталога;
- у 163 импортированных записей есть русские инструкции — это не число всех импортированных упражнений;
- 0 принятых оригинальных 2D-анимаций;
- 0 принятых оригинальных 2D-риг-прототипов;
- все 739 записей остаются `not-started`;
- 26 эвристических candidate buckets, все требуют проверки;
- 160 записей требуют ручной классификации: 3 с явными конфликтами исходных данных и 157 без безопасного совпадения по названию.

**Исправление прежнего подсчёта:** в предыдущем snapshot число 163 было ошибочно принято за количество импортированных упражнений. Фактически 163 — это количество импортированных записей с русскими инструкциями; полный импортированный список содержит 673 записи. Правильный общий объём — 739, а не 229.

Явные конфликтные записи:
- `lib-band-hip-adductions`: название/мышцы указывают на приведение, инструкции — на отведение;
- `lib-side-leg-raises`: инструкция описывает махи ногой в сторону стоя, а мышцы противоречат этому;
- `lib-vertical-swing`: разное оборудование в английском названии и русской инструкции.

Остальные 157 записей без безопасного name-rule match не следует автоматически относить к конкретной биомеханической семье.

## 4. Изменения в Draft PR #305

PR #305 ограничен инвентаризацией, документацией и CI; runtime приложения не меняется.

1. Генератор отдельно разбирает GIF-модули и thumbnail-модули, чтобы 122 require-ссылки не считались 122 уникальными GIF.
2. Общие MP4-ключи, профильные MP4-варианты и PNG-постеры учитываются раздельно.
3. Расхождения orphan/missing GIF вычисляются из текущих файлов и манифеста, без жёстко заданных имён.
4. Количество stable IDs рассчитывается из исходников.
5. Добавлен CI guard `--check`.
6. Дополнительно усиливается проверка: CI должен сравнивать полный сгенерированный JSON и Markdown с ожидаемым результатом, а не только summary/число записей.
7. Вывод ручной классификации должен перечислять только записи с конкретными заметками; 157 записей без безопасного правила показываются отдельным числом, а не строками с `null`.

## 7. Следующий этап

После прохождения инвентаризационного CI и исправления текущих расхождений — Phase 1 именно **2D**:

1. Зафиксировать художественный стандарт персонажа: пропорции, силуэт, анатомические ориентиры, свет/тени и читаемость на маленьком экране.
2. Выбрать архитектуру: оригинальный layered-vector rig или согласованный набор рисованных частей; не возвращаться к отклонённой схематичной SVG-заглушке.
3. Описать суставы, pivot points, порядок слоёв, ограничения и экспорт прозрачных кадров для одного пилотного движения.
4. Создать один короткий цикл и точную привязку к exercise ID.
5. Принимать только после проверки техники, всех кадров, прозрачности, offline playback и Android rendering.

Приседание из PR #33 относится к отдельному 3D-проекту и не закрывает Phase 1 оригинальной 2D-библиотеки.
