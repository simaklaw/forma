## 1. Где мы сейчас (коротко)

За пять проходов закрыт весь список "настоящих заглушек", который было
можно закрыть без нативной сборки и без продуктового решения по каталогу:

- все 3 упражнения дня пишут реальные подходы (вес/повторы редактируются
  степперами, не константы);
- недельный объём, "дней выполнено на неделе", личный рекорд, текущая
  серия дней — всё считается из реальных логов, ничего не захардкожено;
- импорт/экспорт бэкапа восстанавливает весь стор, а не только профиль;
- звук таймера отдыха подключён;
- фоновое фото техники из wger (узкий срез гибридной модели, без смены
  источника каталога);
- заодно найден и исправлен реальный баг компиляции (`Picker` import).

Проверено по-настоящему: `tsc --noEmit` — 0 ошибок, `eslint` — 0 ошибок,
`jest` — по факту добавленных тестов должно стать 55/55 (было 50, +5 в
этом проходе на pruneOldSetLogs/selectOverallPersonalRecord); фактический
`npx jest` в этой среде не прогонялся (нет доступа к npm/сети здесь — см.
HANDOFF.md), стоит подтвердить одним прогоном у себя. Не проверено: реальный запуск в Metro/на
устройстве/в симуляторе — доступа к этому в среде, где ведётся работа,
нет и не будет (подтверждено вами).

## 2. Решение принято: локальный список

**wger как источник каталога упражнений vs локальный список — решено:
остаёмся на локальном.** `WgerExerciseService.fetchExercisesByCategory`
остаётся неиспользуемым для структуры плана (не удалялся — только фото
техники через `searchExerciseImage`, как и было). `WorkoutScreen` расширен
с одного дня ("Ноги — сила") до сплита Push/Pull/Legs — см. `HANDOFF.md`,
«Обновление 8» за деталями (id упражнений, переключатель дня, честная
многодневная семантика для стрика и недельного счётчика).

Нативная сборка (MMKV/Skia/HealthKit/Health Connect/ExecuTorch) больше не
в списке открытых вопросов — вы подтвердили, что локальной среды для неё
нет, и это зафиксировано в `HANDOFF.md` как постоянное (а не временное)
ограничение.
