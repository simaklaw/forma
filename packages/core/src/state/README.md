# Два стора, одна причина

`useFormaStore.ts` и `apps/mobile/src/state/useFitPulseStore.ts` —
**не** одно и то же хранилище с разными именами. Это два независимых
стора, оставшихся от слияния `forma-main` (веб) и `fitpulse-native`
(мобильный).

| | useFormaStore | useFitPulseStore |
|---|---|---|
| Где используется | `apps/web` только | `apps/mobile` только |
| Профиль/вес по умолчанию | `weightKg: 70` (плейсхолдер калькулятора) | `null` (требует онбординг-гейт) |
| Статус | legacy, не трогаем | единственный источник правды для mobile |

**Осознанное решение (зафиксировано в разговоре с продуктом):** не
консолидировать эти два стора сейчас. Причина — консолидация означала бы
либо переписать веб-приложение на мобильную модель профиля (с блокирующим
онбордингом), либо перенести оба на SQLite — обе задачи кратно крупнее,
чем польза от устранения дублирования прямо сейчас, и рискуют сломать то,
что уже стабильно работает на обеих платформах.

**Что это означает практически:**
- `apps/mobile` никогда не импортирует `useFormaStore` — это проверяется
  ESLint-правилом `no-restricted-imports` в `apps/mobile/.eslintrc.js`.
- `apps/web` не обязан (и не должен) перенимать мобильные паттерны вроде
  `isProfileComplete`/блокирующего онбординга — у него свой, более простой
  калькулятор, это осознанно другой UX.
- Если это дублирование когда-нибудь станет болью (например, появится
  нужда делиться профилем между веб- и мобильной сессией одного
  пользователя) — тогда это отдельный проект консолидации, не точечная
  правка. Не пытайся "подправить заодно" в рамках других задач.
